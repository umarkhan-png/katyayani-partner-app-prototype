What v1 is
Ek rule-based helper bot — LLM nahi. 10 fixed intents, chip-first navigation, har jawab ke saath ek rich card aur agla step. Jo iske bahar hai wo seedha human handoff pe jaata hai.
Kyun: partner ke 90% sawaal — "order kahan hai", "refund kab aayega", "iska rate kya hai", "damaged aaya" — fixed answers hain. Inke liye LLM ki zaroorat nahi, aur rule router line-by-line testable hai. v2 me sirf router swap hoga; ye poora UI waisa ka waisa rahega.
v1 scope
✓10 intents (table below)
✓4 read APIs + 1 ticket write
✓5 rich card types
✓Hinglish, chip-first
✗free-text understanding
✗order cancel/modify from chat
✗multi-turn memory

07 · Behaviour Rules & Guardrails
CONTEXT jo open hote hi inject hota hai
(jo pehle se pata hai wo dobara nahi poochhna):
  partner name, verification state, VIP tier
  open orders (last 3), refund in progress, KYC pending steps
  last viewed SKU, current cart

TURN CONTRACT — har bot turn =
  [typing 600–900ms] → [answer ≤ 2 short lines]
  → [0–2 cards] → [next-step chips]

FALLBACK
  miss 1 → "Ye main abhi samajh nahi paaya" + top-4 chips
  miss 2 → auto handoff card (teesri baar nahi poochhna)
  👎 kisi bhi answer par → turant handoff

LANGUAGE
  Hinglish (Roman) default, language.html setting follow karta hai
  chhote vaakya, retailer/farmer vocabulary
  English-only jargon nahi: "out for delivery" theek, "SLA" nahi
KABHI NAHI (v1)
  ✗ unverified partner ko price/margin dikhana → blur + verify CTA
  ✗ crop + stage confirm kiye bina pesticide dose batana
  ✗ refund date promise karna jo backend ne nahi diya
  ✗ chat se order cancel/modify — hamesha screen pe deep-link
  ✗ turn ko bina chip aur bina handoff chhodna (dead-end)

HAMESHA
  ✓ answer me order id / SKU dikhao taaki partner verify kar sake
  ✓ transactional kaam ke liye real screen pe deep-link
  ✓ har unmatched utterance log — yahi list v2 ke intents banayegi
  ✓ thread locally persist — dobara kholne pe resume, reset nahi

v1 SUCCESS METRIC
  Har intent ka "% chats closed without handoff".
  Jo intent 60% se neeche hai use LLM se pehle rewrite karo.
08 · Build Notes (v1 → v2)
v1  Rule router (yahi spec)
    - static intent table, canned copy, real data sirf API reads se
    - 4 read APIs: orders · refund/wallet · KYC state · product by SKU
    - 1 write API: support ticket create
    - zero LLM cost, fully predictable, line-by-line testable

v2  Usi UI ke upar LLM
    - bubbles/cards bilkul same — sirf router swap hota hai
    - v1 ke intents model ke tools ban jaate hain
    - tool call fail ho to v1 ka answer hi fallback rehta hai

Chat screen shell: ai-chatbot.html
  header 56px (back · avatar · "Katyaa · Available 24×7" · ⋮)
  thread padding 16, gap 12
  docked footer = chips row (scroll-x) + input bar
  input bar: attach 40 · mic 40 · field (pill, #F8F8F8) · send 40 #0E7A4E
  scroll-area padding-bottom = 140px + safe-area (footer clearance)
